# 東京23区 用途地域マップ

東京23区の**用途地域・高度地区・防火／準防火地域**を地図上で確認できる静的サイト。
地点をクリックすると建ぺい率・容積率・高さ制限などが表示され、その地点を
**各区の公式都市計画GISで直接開くリンク**が出る。

## できること

- 地図をクリック、または住所検索（国土地理院ジオコーダ）で地点を指定
- 住所がうろ覚えでも **区 → 町名・丁目 → 番・番地** の順に選んで地点に辿り着ける
  （前段を選ぶまで次の段は現れない。番を選んだ時点で地点が確定する。丁目の中でも
  用途地域は変わるため、町名・丁目を選んだ段階では地図を寄せるだけで判定は出さない）
- 住居表示を実施している地区は「○番」、未実施＝地番の地区は「○番地」と自動で
  表記を切り替える（23区では未実施が3.7%あり、新宿区53.6%・千代田区38.5%と偏る）
- 用途地域／高度地区／防火・準防火地域の3レイヤーを切り替え表示
- 地点の詳細：用途地域名・建ぺい率・容積率・高さの最高限度・外壁後退距離・
  敷地面積の最低限度・特例容積率適用地区・高度地区の種別と高さ・防火指定
- 斜線型（第一種〜第三種）の高度地区には北側斜線に関する注意を表示
- 23区中21区は、クリックした地点を**区の公式GISの地図中心**として開ける
- 残る千代田区・杉並区は、区のシステム側に座標を渡す手段が存在しないため、
  **東京都の全都域サービスへ地点指定で**送り、区の公式サイトを補助リンクとして併記する
- 背景地図の切り替え（淡色／標準／航空写真）
- **物件ページのURLを貼ると、その物件の地点を直接開ける**（SUUMO の物件詳細ページ）
- 見ている地点は `?lat=&lon=` としてアドレス欄に残るので、控えておけば開き直せるし人にも送れる
- 検索欄に「35.727372, 139.817497」のように緯度経度を直接貼っても地点になる

## データ

| | |
|---|---|
| 出典 | [東京都都市整備局「都市計画決定情報GISデータ」](https://catalog.data.metro.tokyo.lg.jp/dataset/t000008d0000000028) |
| ライセンス | CC BY 4.0（加工・再配布可。出典表示が必要） |
| データ基準日 | 都市計画決定 令和7年3月31日現在（2026-08時点） |
| 配布元の更新頻度 | 公称「1年ごと」 |
| 区界 | 国土交通省 国土数値情報「行政区域データ」 |
| 住所の選択 | 国土交通省[「街区レベル位置参照情報」](https://nlftp.mlit.go.jp/isj/)令和7年度（23区で89,534街区）<br>無償・加工再配布可、出典明記が条件 |
| 背景地図 | 地理院タイル（国土地理院） |

コード値の意味は同データセットの「データ定義書」に従っている
（用途地域=`TUP3F1`、高度地区=`TUP5F1`、防火=`TUP6F1` ほか）。

**週次ジョブは「毎週データが新しくなる」ものではない。** 配布ZIPの
`Last-Modified` を毎週見張り、**変わった週だけ**取り込んで再デプロイする。
元データが年1回更新なので、ほとんどの週は「変更なし」で即終了する。

## 使い方（ローカル）

`ローカルで開く.bat` をダブルクリック。ブラウザで http://localhost:8787 が開く。
（`file://` で直接開くと、ブラウザの制限でデータを読み込めないので不可）

**`/api/bukken` を使う機能（物件URL検索）は、この .bat では動かない。**
`python -m http.server` は `functions/` を解釈しないため。こちらを使う:

```bash
node build/dev_server.js        # http://localhost:8788
```

静的ファイルの配信に加えて `functions/api/bukken.js` を実際に呼ぶ。
charset も付けて返すので日本語が化けない。

## データを更新する

```bash
pip install -r requirements.txt
python build/build_site.py          # 配布元に更新があった時だけ再構築
python build/build_site.py --force  # 強制的に再構築
```

出力先は `site/data/`。区ごとに分割した GeoJSON と住所ツリー（全体で約13MB）を書き出す。
所要時間は再構築ありで30秒ほど。

## 構成

```
build/
  build_site.py   取得・座標変換・区ごとの分割・書き出し
  codes.py        コード表と配色（表示側にも codes.json として渡る）
  wards.py        23区の定義と各区公式GISのリンクテンプレート
wrangler.jsonc    ← Worker の設定（静的アセットの場所と入口）
worker/           ← サーバー側で動く部分
  index.js        入口。/api/bukken 以外は静的アセットへ渡す
  bukken.js       物件ページから座標だけを取り出す中継
site/             ← これが静的アセットとして配られるフォルダ
  index.html / app.js / style.css
  vendor/         MapLibre GL JS（同梱）
  data/           build_site.py の出力
    youto/ kodo/ bouka/   区ごとの用途地域・高度地区・防火（約11MB）
    juusho/               区ごとの「町名・丁目→番→座標」（約2.4MB）
                          要素は [番, 経度, 緯度]。地番のときだけ4要素目に 1
.github/workflows/weekly.yml   週次の更新チェック
```

地点の判定は、読み込んだ GeoJSON に対する JavaScript 側の内外判定で行っている
（地図の描画状態に依存しないため、描画前でも住所検索が動く）。
表示範囲に入った区の分だけを遅延読み込みする。

# 公開する手順（Cloudflare Workers）

Webサイトを公開したことが無くても進められるよう、順を追って書いてある。
どちらのアカウントも無料。

**このサイトは「静的アセット付き Worker」として動いている。**
`site/` の中身は Cloudflare が直接返し、当たらなかった要求（`/api/bukken`）だけが
`worker/index.js` に降りてくる。静的ファイルの配信は無料のままで、
無料枠（10万リクエスト/日）を使うのは物件URL検索のときだけ。

> 以前この節には Cloudflare **Pages** の手順が書いてあったが、実際の配信は
> Worker だった（`*.workers.dev` は Worker 専用のドメインで、Pages は使えない）。
> Pages 専用の `functions/` は読まれないため、`worker/` に作り直してある。

## 1. GitHub にコードを置く

1. https://github.com/signup でアカウントを作る
2. https://github.com/new で新しいリポジトリを作る
   - Repository name：`youto-map` など
   - **Public**（Cloudflare Pages の無料枠は Private でも使えるが、Public の方が手順が少ない）
   - 「Add a README file」等のチェックは**入れない**
3. このフォルダ（`youto_map`）を、作ったリポジトリに push する

```bash
cd youto_map
git init -b main
git add .
git commit -m "東京23区 用途地域マップ"
git remote add origin https://github.com/<あなたのID>/youto-map.git
git push -u origin main
```

`site/data/` の約13MBもそのままコミットする（Cloudflare Pages はリポジトリの中身を
そのまま配信するため）。

## 2. Cloudflare Workers につなぐ

1. https://dash.cloudflare.com/sign-up でアカウントを作る
2. 左メニュー **Workers & Pages** → **Create** → **Import a repository**
3. GitHub を認証し、`youto-map` リポジトリを選ぶ

設定は `wrangler.jsonc` に書いてあるので、ダッシュボード側で入力するものは無い。

```jsonc
{
  "name": "youto-map",          // Worker 名。変えると別のURLになる
  "main": "worker/index.js",    // 入口
  "assets": { "directory": "./site", "binding": "ASSETS" }
}
```

`https://youto-map.<アカウント名>.workers.dev/` が発行され、
以降は GitHub に push するたびに自動で再デプロイされる
（ダッシュボードの **Deployments** に push ごとのビルドが並ぶ）。

独自ドメインは **Domains** から追加できる
（Cloudflare でドメインを管理していれば SSL 込みで無料）。

## 3. 週次の自動更新を有効にする

`.github/workflows/weekly.yml` が入っているので、push した時点で有効になる。

- 毎週月曜 07:00（日本時間）に配布元の更新を確認する
- 更新があった時だけ `site/data/` を再構築してコミット → Cloudflare Pages が自動デプロイ
- GitHub の **Actions** タブから手動実行もできる（`force` を on にすると強制再構築）

> GitHub Actions は、リポジトリに60日間まったく変更が無いとスケジュール実行を
> 自動停止する。元データが年1回更新なので、これに引っかかる可能性がある。
> Actions タブで手動実行するか、たまに何かコミットすれば再開する。

## 物件ページのURLから地点を出す仕組み

不動産ポータルの物件ページには、地図を描くための座標がHTMLの中に入っている。
これを読めば、住所が丁目止まりでも物件の地点そのものを特定できる。

```
SUUMO の物件ページ
  var googleMapsSettings = {
      initIdo : '35.7273717958878'      ← 初期表示の緯度
    , initKeido : '139.817497202439'    ← 初期表示の経度
    , markers: new Array(
        {lat:'35.7273717958878', lng:'139.817497202439', ...}   ← ピンそのもの
      )
  }
```

ブラウザから他サイトを直接読むことは CORS で出来ないため、`worker/bukken.js` が中継する。
入口は `worker/index.js` で、静的アセットに当たらなかった要求だけがここに降りてくる。

**取り出すのは座標だけ。**物件名・価格・説明文は受け取らないし返さない。
用途地域の判定に要るのは座標だけで、それ以外を持ち出せば転載になる。

中継が守っている条件:

| | |
|---|---|
| 行き先 | `suumo.jp` のみ（許可リスト方式）。任意のURLを踏めると踏み台になるため |
| 経路 | robots.txt が `User-agent: *` に禁じている `/jj/` `/mb/` `/sp/` `/edit/` `/display/` `/journal/` は拒否 |
| ページ種別 | 末尾が `nc_<数字>` の物件詳細ページのみ。一覧や内部APIは拒否 |
| 座標の検査 | 23区の範囲外（緯度35.5〜35.9・経度139.5〜139.95の外）なら読み違いとして捨てる |
| 配布元への負荷 | 同じ物件は24時間キャッシュし、繰り返し叩かない |

SUUMO の robots.txt は 2026-10-25 に確認（381行）。物件詳細の `/tochi/` `/ikkodate/`
`/ms/` `/chuko/` に対する `Disallow` は無く、`Crawl-delay` も bingbot にしか付いていない。

**壊れるとすれば配布元のHTML変更。**その場合は「座標を読み取れませんでした」と出て
住所検索へ案内するだけで、黙って誤った地点を出すことはない。
対応サイトを増やすときは `ALLOW_HOSTS` と `extractCoords()` に足す。

## 制約と注意

- **このサイトは参考情報**。用途地域の境界は道路中心線や敷地境界と厳密には
  一致しないことがあり、境界付近の土地は必ず区の窓口で確認すること。
  そのために各区公式GISへのリンクを置いている。
- ポリゴンは1mの許容誤差で簡略化してある（表示サイズを抑えるため）。
- 区界でクリップする際、隣接区とわずかに重なるよう約30m外側に広げている
  （境界に隙間が出ないようにするため）。
- 千代田区は高度地区の指定そのものが無い。

### 各区公式GISへのリンクについて（2026-08-07 調査）

千代田区と杉並区は、**区のシステム側に地点を渡す口が存在しない**ことを確認済み。

- 千代田区（ArcGIS Experience Builder）… URLパラメータ非対応。`center` を緯度経度でも
  地図の座標系（平面直角座標系 sr=2451）でも渡したが、`identify` の座標も `mapExtent` も
  毎回まったく同一で、常に既定範囲を読む。
- 杉並区（すぎナビ・Vue）… ルーター定義が `/mp/:mp` と `/mp/:mp/vlf/:vlf` のみで、
  クエリパラメータを読む処理が `app.js` に1箇所も無い。旧UI `/webgis/` は未提供。

この2区は東京都都市整備局の
[都市計画情報等インターネット提供サービス](https://www2.wagmap.jp/tokyo_tokeizu/)（全都域）へ
地点指定で送っている。今回のデータの発行元そのものなので、出典としても筋が通る。

**このサービスの `mpx`/`mpy` は日本測地系として解釈される。** `gprj` の値を変えても
変わらない。世界測地系のまま渡すと約460m北西へずれるため、`app.js` の
`wgs84ToTokyo()` で変換してからURLに埋めている。

検証結果（変換後の座標を渡し、サイト側の座標表示・現在地表示と突き合わせ）：

| 地点 | 現在地表示 | 誤差 |
|---|---|---|
| 中野区沼袋1-32-1 | 中野区沼袋１丁目 | 0.9m |
| 千代田区丸の内 | 千代田区丸の内１丁目 | 1.7m |
| 杉並区阿佐谷 | 杉並区阿佐谷南１丁目 | 1.6m |

中央区は当初トップページ送りにしていたが、`map.php?lat=&lon=` が利用許諾に阻まれず
直接開き、タイル座標が指定地点と一致することを確認したため、地点指定リンクに変更した。
